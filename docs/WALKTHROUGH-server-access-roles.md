# server-access-roles 实际走查手册（Owner 版）

> 目标：不读任何文档的"包租婆"，用这份手册亲身体验三角色故事——
> 陌生人敲门 → 你在管理台看到并一键放行 → 对方进楼；
> 发一张邀请码 → 对方在客户端自助注册成租户；
> 拉黑/到期/节点切换各自生效。
>
> **先纠正一个常见误会**：`http://39.107.213.167:18787` 是**服务器**
> 的公开服务清单页（healthz/services.json 本来就是公开面）——那不是
> 管理台。**管理台（webui）是你本机启动的 sidecar 进程**，它持有
> admin token 并把请求代理到服务器；token 不进浏览器、不落盘。

## 第一幕 · 打开你的管理台（终端 1）

```sh
./scripts/walkthrough/webui-demo.sh
```

预期输出：一段横幅，其中 **`管理台地址 : http://127.0.0.1:18950` ← 浏览器打开这个**
（macOS 会自动打开）。终端还会打印一行 `node book add code: XXXX`——这是第五幕
节点簿添加节点用的配对码，先不管。

浏览器里你会看到四页（左侧导航）：

| 页 | 看什么 |
|---|---|
| 总览 | 四问：谁在线 / 几个租户 / 有没有人敲门 / 邀请码状态 |
| 租户管理 | 名册（别名+缩写+到期）、续期、**邀请码管理** |
| 访客与门禁 | **敲门台**、访客名册、黑名单 |
| 在线连接 | 谁在线（含访客，按端点/按访客分列） |

> 顶栏可能出现"明文连接"告警——demo 是 http 公网地址，属预期。

## 第二幕 · 有人在敲门（终端 2）

```sh
node scripts/walkthrough/knock.mjs \
  --relay http://39.107.213.167:13340 \
  --gateway http://39.107.213.167:18787 --token demo-admin-token
```

这是"陌生设备模拟器"：用一把一次性钥匙无票连接你的服务器。它会打印自己的
公钥和缩写，然后保持运行、每 2 秒汇报自己是否在线。

**回到浏览器**：访客与门禁 → 敲门台——应该出现一条待处理敲门（缩写/次数/
原因"陌生设备，无通行票"）。点 **「定位为访客」** 并确认。

**回到终端 2**：几十秒内（relay 重试退避，通常 10~60s）会打印
`🎉 已进楼！…在线`。浏览器"在线连接"页同时出现该端点、角色标记访客。

> 敲门台四个动作的语义：定位访客=进楼无房间；导入租户=引导用邀请码；
> 拉黑=彻底拒绝；忽略=暂不处理（它再敲会自动回到待办）。

## 第三幕 · 拉黑一个设备

敲门台该行点 **「拉黑」**。注意看终端 2：**它不会立刻掉线**——这是有意的
语义（存量连接自然结束，**新连接**一律被拒，且它不再出现在敲门台）。
要亲眼看到"进不来"：

```sh
# 终端 2：Ctrl+C 退出，然后用同一把钥匙重敲（= 同一台设备再来）
node scripts/walkthrough/knock.mjs \
  --relay http://39.107.213.167:13340 \
  --gateway http://39.107.213.167:18787 --token demo-admin-token \
  --data-dir /tmp/my-knocker-key
```

（第一次用 `--data-dir` 时会生成钥匙并保留在 `/tmp/my-knocker-key`；之后再
Ctrl+C 重跑同一命令就是同一台设备。）预期：它永远停在 `状态：未上线`，敲门台
不再新增它的记录（黑名单不入待办）。去黑名单页把它移出，再重跑一次——又进楼了。

## 第四幕 · 发邀请码，租户自助注册

1. 浏览器：租户管理 → 邀请码 → **签发**（默认 1 次 / 7 天 / 注册后 30 天，都可改）。
   签发结果页会**只显示一次**码全文（`dwebc1.xxxx-xxxx-xxxx-xxxx`）——复制它。
2. **终端 3**（扮演想入驻的新租户，用隔离的 key 演示）：

```sh
DWEB_HOME=/tmp/new-tenant node packages/opendweb/bin/opendweb.mjs join \
  --server http://39.107.213.167:18787 \
  --code dwebc1.粘贴刚才的码 --allow-insecure
```

预期输出（实测样例）：`fabric_id …(newly generated)`、`expires 2026-10-23`、
`receipt verified`、`state /tmp/new-tenant/registration.json`。
3. 回浏览器租户管理：名册多出一行（你的邀请码别名提示 + 缩写 + 30 天到期）。
4. 同码再给别人用：`code-exhausted` 被拒（一人一码；本人同码重试=幂等回放不续期，
   续期请再签新码——这是防"旧码变永久续租凭据"的有意设计）。

> 不加 `DWEB_HOME` 时 join 用你本机默认钥匙（`~/.opendweb/identity.key`，
> 一台设备一把——`opendweb id` 可随时查看，与节点握手用同一把）。

## 第五幕 · 节点簿：一次管一台，右上角切换

浏览器右上角当前节点掩码地址 → 打开节点簿面板 → **添加节点**：
填另一台服务器地址+token，配对码用**终端 1**里 `node book add code:` 打印的
那个（10 分钟有效；过期会打印新的）。添加成功后点「切换」——**立即生效、
无需重启**，页面数据自动变成新节点的；两个节点的门禁互不影响。
（凭证只存在本机 `~/.opendweb/nodes.json`，权限 0600，浏览器永远看不到。）

## 第六幕 · 到期与续期

租户管理任一行「续期」改成 1 天 → 名册出现倒计时预警。到期的精确边界
（当天即拒、deny reason 区分、续期恢复）已由自动化测试钉死（见附录 A），
无需手工等一天。

## 附录 A · 已经自动化验证过的边界（不用手工测）

## 附录 B · 完全本地的走查（不用云端）

```sh
# 终端 0：本地起一台 restricted 服务器（一次性数据目录）
DWEB_ADMIN_TOKEN=local-token DWEB_DATA_DIR=$(mktemp -d) \
  /Users/kzf/.cargo-target/dweb/debug/dweb-server \
  --access-mode restricted --gateway 127.0.0.1:18790 --relay 127.0.0.1:13343

# 之后各幕命令里把服务器换成：
#   --server/--gateway http://127.0.0.1:18790，token local-token，
#   --relay http://127.0.0.1:13343，且 webui-demo.sh 加 NO_INSECURE=1
```

## 常见问题

- **打开 18787 是服务清单页** → 正常，那是服务器的公告面；管理台永远是本地的 `127.0.0.1:<port>`。
- **端口被占** → `PORT=18951 ./scripts/walkthrough/webui-demo.sh`。
- **放行后对方迟迟不在线** → relay 重试退避（最长约 1 分钟），敲门器会自动汇报；着急可 Ctrl+C 后同 `--data-dir` 重跑（退避清零）。
- **想清空敲门台** → 每行「忽略」；当前云端 demo 里的 3 条待办是此前验收留下的真敲门，可直接拿来练手。

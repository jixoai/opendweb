## 1. 产品定义

### 1.1 一句产品定义

**home-hub 把家里的一台常开机器一键变成全家的网络聚点。** 家长不需要懂服务器，
家庭成员不需要懂网络：扫码进来、敲门进来，进来之后设备之间直连。

### 1.2 中枢是什么 / 不是什么（[H3] 的产品化表述）

中枢 = 家庭网络里被显式指定的一台管理节点。给用户的全部解释只有三句话（这三句
是产品文案的冻组件，init 确认、总览引导、帮助文案三处同源）：

> **中枢只管三件事：帮家里人互相找到对方（牵线）；直连暂时建立不起来时兜底中转
> （兜底）；决定谁能进（守门）。**
> **家人互传的数据不经过中枢——设备之间直连，只有兜底时才借道。**

「中枢不是流量瓶颈」不是工程注释，是用户承诺（G-3 对拍后的精确口径，
design §7）：**已直连**的成员设备互传不受影响；**借道中**的设备会暂时
断开、中枢回来后自动恢复；中枢回来，新成员又能进（验收口径 §7.4）。
若实现不满足，上引两段文案必须收回——禁止文案先行于事实。

| 中枢是 | 中枢不是 |
|---|---|
| 显式选择的一等本地服务（一次 init 点亮；不默认常驻 [H3]） | 不是每台设备都跑的默认组件 |
| 寻址（rendezvous）+ 回退（relay）+ 门禁（三角色）的宿主 [H3] | 不是流量瓶颈（数据面 P2P 直连；局域网现成，IPv6 铺开后自动受益） |
| 家庭场景对既有三角色的包装（restricted 门禁/邀请码/敲门/webui 全部现成 [H3]） | 不是新内核、新协议、新准入机制 |
| 生命周期被托管的服务（开机自启、状态可见、异常可察 [H2]） | 不是 NAS、不是路由器、不存家人的数据 |
| 接入信息的发出方（二维码/短码/手动地址 [H1]） | 不做局域网自动发现（mDNS 非核心 [H1]，后续可选增强） |

### 1.3 三视角：这台设备的三张脸（[H5]）

server-access-roles 的 webui 只有一张脸（管理员管理台）。[H5] 把它升级为一个
切换器下的三张脸——**同一台设备与 opendweb 网络的三种关系**：

| 视角（组 B 命名，[H7] 已拍板） | 这台设备是谁 | 数据来源（真源） | 界面 |
|---|---|---|---|
| **我的中枢**（=原「我的服务器」） | 管中枢的人（包租婆；家里通常是家长机） | 节点簿（本机 nodes.json）+ 远端 `/admin/*`（sidecar 注入管理凭证） | 既有四页管理台 + 接入卡片（§3.2） |
| **我的租约**（=原「我的服务商」） | 别家服务器的租户（家庭成员的常态） | 本机租约簿 leases.json（join 写入，0..N；现状单条 registration.json 由设计迁移） | 单页租约列表 + 详情（§3.3） |
| **我的到访**（=原「我的到访」） | 被放行过的访客 | 本机到访簿（visits；放行后尽力记录 + 按需探测） | 单页到访列表（§3.4） |

首现定义：**租约** = 一台设备在一台服务器上的注册关系（属于哪个 Fabric、什么时候
到期）；**到访记录** = 本机被放行进楼后，本机尽力留下的连接记录（best-effort，
只存在这台设备上，不保证完整——诚实呈现纪律见 §3.4）。

三条视角隔离铁则（IA 完整性的底线）：

1. **视角决定全局渲染** [H5]：导航、首屏、顶栏状态位随切换器整体切换，不是叠加
   Tab。租约视角下不出现任何 admin 概念（节点簿、健康灯、管理凭证字样）；中枢
   视角下不出现成员倒计时。
2. **数据互不串扰**：三视角三个本地真源（节点簿/租约簿/到访簿），互不写对方。
3. **成员设备打开 webui 不是错误状态**：无 hub.json 且有租约/到访数据的
   设备打开 webui 直接落租约/到访视角（member 态），不进 setup——但**零本地
   数据的设备仍进 setup**（基线保留：首次配对入口不破坏；`--setup` 为强制
   通道；本机有 hub.json 则自动 admin）。五行动流表见 design §4.2（r2 修订）。

### 1.5 对象树增量（接续 server-access-roles §1.4）

```
设备（DWEB_HOME）
 ├─ 节点簿 nodes.json（中枢视角真源）—— 既有，不改
 │    └─ 当前节点 → 既有对象族（租户名册/访客名册/黑名单/敲门台/邀请码/在线）
 ├─ 租约簿 registration（租户视角真源；0..N 条）※现状单条存储，见 G-1
 │    条目：服务商地址 + 备注（本地） + 我的 fabric + 根端点缩写 + 到期 + 回执
 │    生命周期：join 兑换 → 在租 → 临期(≤7天) → 已到期(新连接被拒)
 │              → 新码重新加入（同设备同 fabric，门牌与别名不变）
 ├─ 到访簿 visits（到访视角真源；best-effort）※新增账本，见 G-2
 │    条目：对端地址 + 备注 + 最近连通探测（结果/时间）
 └─ 中枢身份（本机 init 之后才有）：数据目录 + 管理凭证 + 家庭端口 + 自启配置
```

旅程映射：家长 `hub init` → 中枢身份 + 接入卡片 → 成员扫码/输短码/填地址 →
敲门（访客路径）或 join（租户路径）→ 名册/到访簿各自落账 → 租期节点回
租约视角（临期→续期→在租）。中枢停机 → 已直连成员互传不受影响（§1.2 口径）。

## 2. 使用叙事（四个，步骤级）

### 叙事 H1：把书房的 Mac mini 变成家里的中枢（P6）

1. 周五晚上，你在 Mac mini 终端敲 `opendweb hub init`。
2. 终端先给确认（§4.2 逐字文案）：这台机器会变成家里的中枢、门禁开启、管理凭证
   只落本机、家人互传不经过这台机器。你按 y。
3. init 自检网络：`自检通过：家里人应该能连上 http://192.168.2.13:8787`。
4. 终端打印接入卡片（§4.4）：中枢名「Mac-mini-书房」、地址、短码、二维码、
   家里人的三步。
5. 终端顺势引导开机自启，你按 y：`已开启。重启机器试试：中枢会自己回来。`
   你关掉终端去吃饭——中枢在跑。

### 叙事 H2：新成员加入——扫码、敲门、放行（V1 + P2）

1. 弟弟拿到新笔记本。你把接入卡片给他看（终端重打：`opendweb hub card`）。
2. 他扫二维码拿到地址，客户端连上去——门禁拦下：`敲门已送达，等待放行`。
3. 你的托盘图标角标变 1；菜单第一行写着 `中枢：运行中 · 1 台设备在敲门`。
4. 点托盘 → 直接落在敲门台（点击落点规则 §3.6）——正是弟弟那台设备，
   缩写 `k7f2***9a1c`，原因「陌生设备，无通行票」。
5. 你电话核对尾号，点「定位为访客」。弟弟那边重连即通。
6. 弟弟的 webui 里「我的到访」从此多一条：这栋楼、可连通。他自己的机器名显示
   在自己设备上；你名册里他是缩写（§5.3 边界）。
7. 一个月后他要在家里跑自己的 Fabric，你改走邀请码路径（N2 既有流程不变），
   他 join 成租户，「我的租约」多了一条，30 天后开始倒计时。

### 叙事 H3：路由器断电重启，中枢自己回来（P7）

1. 周末路由器断电重启。Mac mini 也跟着重启了。
2. 开机自启生效：中枢进程自己回来，托盘图标回到常态。
3. 但路由器给 Mac mini 重新分了地址。弟弟连不上，客户端话术指路：
   `连不上中枢。可能是家里网络的地址变了——请中枢的主人跑 opendweb hub status 看一眼。`
4. 你跑 `hub status`：`地址：http://192.168.2.20:8787`，附提示行：路由器动态
   分配地址，建议固定。你照提示在路由器里绑定，问题不再复发。
5. `opendweb hub card` 重打卡片，弟弟扫新码，一切照旧——他的访客身份和到访
   记录都还在（身份跟密钥走，不跟地址走）。

### 叙事 H4：租约临期与续期（T5/T6）

1. 弟弟打开 webui，右上角切换器默认落在「我的租约」（他这台设备没有中枢）。
2. 首屏黄条：`你的租约还剩 5 天`，正文写明两件事：找谁（这台服务器的管理者）、
   怎么办（请他续期，或拿新邀请码重新加入——同设备同网络，门牌不变）。
3. 他找你。你在管理台名册行点「续期 → 顺延 30 天」（N3 既有流程）——他重连即通
   （服务端已续）；他本机的倒计时数字是**本地快照**，要等他下次持新码加入才刷新
   （黄条副文案已写明这一语义，r2-P1-5 冻结）。
4. 假设没续上：到期后新连接被拒（客户端既有话术 `租期已到`），租约视角红标附
   新码重进命令；他拿新码 join 同 fabric 重进，别名与门牌不变。

## 3. 信息架构：三视角控制台（[H5]，核心章节）

### 3.1 右上角身份切换器

```
┌ 顶栏：品牌 ····· [视角切换器：我的中枢 ▾] ·（视角专属状态位）
│                      ├ 我的中枢      [敲门徽章 n]
│                      ├ 我的租约      [临期徽章 n]
│                      └ 我的到访      （无徽章）
├ 视角＝我的中枢：setup 世界(一次性) / ready 世界(总览·租户管理·访客与门禁·在线连接)
├ 视角＝我的租约：单页（租约列表 → 行内展开详情与续期指引），无侧栏导航
└ 视角＝我的到访：单页（到访列表 + 连通探测），无侧栏导航
```

- **位置与形态**：顶栏最右，当前视角名 + 下拉；三项 + 各自徽章。切换器是全局
  身份锚点，三视角共用外壳（顶栏常驻），空间连续性靠它维持——租约/到访视角
  导航区收起，内容单页直给（两页内容量撑不起侧栏，不虚构层级）。
- **默认视角**：首次进入按数据自动选择（本机中枢在跑→中枢；否则有租约→租约；
  否则到访；全空→中枢视角引导态）。此后记忆最近使用。
- **切换语义**：一击切换、整页重渲、无确认（低后果：只是看的角度）。切换器
  徽章与各视角页内待办同源（§3.5）。
- **首次进入引导**：中枢视角沿既有 setup 世界；租约视角空态给三步加入指引
  （§3.3）；到访视角空态给教育文案（§3.4）。均不做弹窗教学。

### 3.2 视角一「我的中枢」（管理员，既有管理台 + 一张新卡）

- **页面结构**：ready 世界四页原样（总览/租户管理/访客与门禁/在线连接，
  server-access-roles §3.2 冻结）；顶栏健康灯、节点簿面板原样。
- **新增：接入卡片卡**（真源，§3.5）：总览引导区置顶、可折叠、常驻——
  「家里人怎么连」：中枢名（本机机器名 [H6] 称呼层）+ 地址 + 短码 + 二维码
  + 「邀请码不放在卡片上，去租户管理单独签发」注（§4.4）。
- **空态**：未配任何节点 → 既有 setup 世界；本机 init 过但中枢未在跑 → 总览
  置一张中枢状态卡：`中枢没有在运行` + 「启动中枢」（converge 到 `hub start`
  同一动作面）。
- **数据**：节点簿 + sidecar 反代 `/admin/*`（既有，不改）。

### 3.3 视角二「我的租约」（租户）

- **首屏两问 3 秒答**：还剩几天（倒计时/状态列）· 现在连得上吗（连通探测）。
- **结构**：租约列表（默认落地）——每条：备注名（本地可改，缺省掩码地址）·
  服务商地址 · 我的身份（机器名 + 根端点缩写 [H6]）· 状态（在租/临期/已到期）
  · 到期时间。行内展开详情：fabric 缩写、回执、续期指引（双路径文案 §4.4 表）。
- **空态与首次引导**：
  > **这台设备还没有加入任何网络。**
  > 三步加入：① 向网络的主人要接入卡片（地址）；② 要一张邀请码；
  > ③ 终端运行 `opendweb join --server <地址> --code <邀请码>`。
  >（加入动作发生在终端/客户端，本页只指路——本轮不做页内 join 表单。）
- **数据**：本机租约簿（registration）。0..N 条（存储演进见 G-1）。

### 3.4 视角三「我的到访」（访客，best-effort 的诚实呈现）

- **结构**：到访列表——每条：对端（备注/地址缩写）· 最近连通探测（结果/时间）
  ·「测一下」动作。首屏两问：我到访过的楼哪些还通 · 上次什么时候。
- **诚实呈现纪律（O-3 的产品面约束）**：页脚常驻一句：
  > 到访记录只保存在这台设备上，尽力而为——不保证完整。
  「连不上」的话术不误导：`连不上。通常是那台服务器没开机，不代表你被拒——
  被拒会有明确提示。`探测是主动动作（v1 不自动轮询，避免家庭网络里无意义心跳）。
- **空态**：
  > **还没有到访记录。**
  > 你敲开一栋楼的门、被放行之后，这里会记下这栋楼。
- **数据**：本机到访簿（visits，新增账本，归属见 G-2）。

### 3.5 真源规则（One Concept → One Canonical Location）

| 概念 | 真源 | 快捷入口（必须 converge） |
|---|---|---|
| 接入卡片（地址/短码/二维码，同一数据三形态） | 中枢视角·总览「家里人怎么连」卡 | CLI `hub init` 尾部 / `hub card` 重打——与 webui 卡片同一生成源 |
| 租约状态与倒计时 | 租约视角 | 客户端 deny 话术指路（§5.3 沿用），不在他处重复账本 |
| 到访记录 | 到访视角 | — |
| 敲门待处理计数 | 中枢视角·访客与门禁（既有） | 切换器徽章、托盘角标、总览待办条、托盘菜单状态行——同一数据源 |
| 中枢运行状态 | 进程事实（`hub status`） | 托盘图标、总览健康灯/中枢状态卡 |
| 开机自启开关 | `hub autostart` | 托盘菜单勾选项——写回同一配置 |

### 3.6 托盘 = 三视角状态聚合（[H2]）

托盘是 opendweb 插件（`opendweb tray`，marketplace 可装、可选、核心不依赖）；
点开即 webui（经 webui SDK 进程内唤起 [H4]，可深链）。

**图标状态（优先级从高到低，同时只呈现一个）**：

| 优先级 | 状态 | 图标 | 语义 |
|---|---|---|---|
| 1 | 异常 | 警示态 | 该运行而未运行（自启开了但进程不在）/ 进程失联 |
| 2 | 敲门待处理 | 常态 + 数字角标 n | n 台设备在等放行（与敲门台同源） |
| 3 | 运行中 | 常态 | 一切正常 |
| 4 | 未配置 | 灰态 | 本机无中枢（纯成员机装了托盘的降级呈现，v1 边界见 O-5） |

**点击落点**（点图标 = 打开控制台，按当前最需关注的事深链）：有待处理敲门 →
敲门台；异常 → 总览（中枢状态卡）；运行中 → 总览；未配置 → 租约视角。

**菜单逐字（v1）**：

```
中枢：运行中 · 1 台设备在敲门      （状态行，不可点）
──────────
打开控制台
停止中枢                        （运行时；停止时显示「启动中枢」）
开机自启 ✓
──────────
退出
```

## 4. 中枢生命周期体验

### 4.1 命令族：用户语言（命名预设见 O-2）

| 命令 | 用户语言（help 首行） |
|---|---|
| `opendweb hub init` | 把这台机器变成家里的中枢（一次性：预设+自检+接入卡片） |
| `opendweb hub start` / `stop` | 启动 / 停止中枢（start 后台守护） |
| `opendweb hub status` | 中枢现在怎么样：运行状态、地址、成员、敲门、自启、排障提示 |
| `opendweb hub autostart on / off` | 开机自动把中枢带回来 / 关掉 |
| `opendweb hub card` | 重新出示接入卡片（家里人怎么连） |

预设 A（推荐）`opendweb hub`：hub=「中枢」直译，与视角名「我的中枢」互指。
预设 B `opendweb home`：更「家」，但把产品窄化为家庭-only（工作室共享也是中枢）。
预设 C `opendweb server --preset family`：preset 藏进 flag，proposal Why#1 要逃的
正是裸 server 命令的无发现性。**已由 [H7] 拍板（2026-09-23）：预设 A `opendweb hub` 族，`card` 子命令定名**。另增 `opendweb hub open`（本机管理员入口，r2-P1-2）。

### 4.2 流 F1：首启 `hub init`（逐字文案）

| 步 | 界面行为 | 成品文案（终端） |
|---|---|---|
| 1 | 确认（知情前置：做什么/不做什么/凭证边界） | **把这台机器变成家里的中枢？**<br>这台机器：Mac-mini-书房 · 家庭端口：服务 8787 · 中转 3340（可改）<br>将发生什么：<br>· 起一台家庭服务器，**门禁开启**——只有你放行的人、和你发过邀请码的人能进<br>· 生成**管理凭证**，保存到本机私有文件——不显示、不离开这台机器<br>· 自检网络，告诉你家里人能不能连上<br><br>中枢只管三件事：牵线、兜底、守门。**家人互传的数据走设备直连，不经过这台机器。**<br>继续？(y/N) |
| 2 | 管理凭证落地（无输出——不显示是纪律） | `管理凭证已保存到本机（仅这台机器的用户可读）。` |
| 3a | 自检·通过 | `自检通过：家里人应该能连上 http://192.168.2.13:8787。` |
| 3b | 自检·警告（防火墙） | `自检发现：防火墙可能挡住了端口 8787，家里人可能连不上。`<br>`去系统设置的防火墙里放行 opendweb，然后运行 opendweb hub status 重新自检。` |
| 3c | 自检·失败（端口被占） | `端口 8787 已被其他程序占用。`<br>`换端口重来：opendweb hub init --gateway 18787；或先停掉占用它的程序。` |
| 4 | 打印接入卡片 | 见 §4.4 |
| 5 | 自启引导（非强制） | `要不要开机自启？这台机器重启后，中枢会自己回来。（随时可关：opendweb hub autostart off）`<br>确认后：`已开启。重启机器试试：中枢会自己回来，托盘图标会亮起。` |

防火墙指引按平台各给一句话路径（macOS：系统设置→网络→防火墙；Windows：
Windows 安全中心→防火墙），不内嵌自动化改防火墙——**产品不做越权系统变更**。

### 4.3 流 F2：起停与自启

- `hub start`：`中枢已启动：http://192.168.2.13:8787。`（后台守护；出口不阻塞终端）
- `hub stop`：确认一句：`停止中枢？家里人将无法新连接；已互相直连的设备不受影响。` → `已停止。`（口径 §1.2）
- `hub autostart` 确认：`将为当前用户安装系统服务（不需要管理员密码）。这台机器
  重启后中枢自动回来。`→`已开启。`（off 无确认）
- `hub status` 成品样例：

```
中枢：运行中
机器：Mac-mini-书房
地址：http://192.168.2.13:8787（局域网）
成员：2 个租户 · 1 个访客在线 · 1 台设备在敲门
开机自启：已开启
提示：路由器给这台机器的地址是动态分配的，建议在路由器里固定它，
      否则重启后地址可能变化（变了就重新出示接入卡片）。
```

### 4.4 流 F3：接入信息卡片（[H1] 三形态，同一数据源）

卡片承载**地址与引导**；身份与准入仍走既有协议（敲门/邀请码）[H1]——卡片上
**没有邀请码、没有凭证**（是否放宽见 O-8）。

```
── 接入卡片 · 家里人怎么连 ────────────────────
中枢：Mac-mini-书房
地址：http://192.168.2.13:8787
短码：dwebh1.7k2q9-m4tv3-xa2b9 （电话里念给对方，等于上面的地址；IPv4 固定 15 字符形态示意，实际编码由冻结算法生成——design §3.1）
二维码：▓▓▓▓  （扫一下，得到上面的地址）

家里人的三步：
 1. 装 opendweb
 2. 扫二维码 / 输短码 / 手动填地址，连上中枢
 3. 等放行——家长在中枢管理台点「定位为访客」；
    要自己的房间，就找家长拿邀请码注册成租户
──────────────────────────────────────────────
```

- **二维码**：扫码即得地址（本机局域网地址；未来 IPv6/公网地址同位呈现）。
- **短码**：中枢地址的防错短编码（人类可念、防听错）。产品要求：**离线自解**——
  客户端内置规则直接解码，不依赖任何在线解析服务（朴素可靠 [H1]；若技术侧
  裁决需要在线解析，须回 Owner 重议，见 G-5）。
- **手动地址**：文本 + 复制。
- webui 卡片（中枢视角·总览）与终端打印同源同文案；附注：
  `邀请码不放在卡片上——要发给谁，去 租户管理 → 邀请码 单独签发。`

### 4.5 成员侧文案：临期提醒与重进（租户视角 + 客户端）

| 场景 | 成品文案 |
|---|---|
| 临期黄条（≤7 天） | **你的租约还剩 5 天。**（本地快照）<br>这台服务器的租期到 9 月 28 日。续期由管中枢的人完成：请他续期，或向他要一张新邀请码后重新加入——同设备同网络，门牌不变。若管理者已为你续期，这里会在你下次持新码加入时刷新；能否连上以实际连接为准。 |
| 已到期红标 | **租约已到期（9 月 23 日）。新连接正被拒绝。**<br>要一张新邀请码，然后重新加入：`opendweb join --server http://192.168.2.13:8787 --code <新码>` |
| 客户端连不上中枢（排障指路） | **连不上中枢。**可能是家里网络的地址变了——请中枢的主人跑 `opendweb hub status` 看一眼。 |

deny 话术映射（owner-expired / blocked / 敲门语境）全部沿用 server-access-roles
§5.3 冻结文案，不重复维护。

## 6. 设计方向增补（方向 B 台账基座上的新面气质约定）

不新开方向。Convention 赛道延续，新增面只约定气质：

- **切换器 = 身份锚点**：顶栏最右、当前视角名 + 下拉；克制、无头像化装饰；参照
  GitHub 账号切换器的「一个控件解释整个应用结构」的角色。徽章只承载待办计数。
- **接入卡片 = 凭证面**：二维码是视觉主角、地址等宽、短码大字可念；可整卡打印
  （贴冰箱场景是真实使用画像——纯文本排版在 A4 上依然可读）。
- **租约/到访页 = 单页台账**：低密度、倒计时人类可读（「剩 5 天」而非日期戳）、
  状态列语义色克制（黄临期/红到期，不整行染色）。
- **托盘 = 状态聚合，不是功能面板**：菜单 ≤7 项；图标三态语义在系统通知区可辨
  （不依赖颜色 alone：异常态附点位提示）。
- 红线自检（anti-patterns 延续）：无渐变、无发光、无玻璃拟态；语义色只进状态；
  徽章不堆叠。

## 7. 验收标准（小白可检验）

1. **零文档变中枢**：没读过文档的家长在常开机器上一条 `opendweb hub init` 走完
   确认→自检→卡片→自启，全程无未解释术语，≤5 分钟；期间终端不出现 daemon/
   token/restricted 等工程词（管理凭证/后台/门禁等用户词除外）。
2. **零文档成员加入**：成员扫卡片二维码→敲门→家长托盘角标 +1→点开落敲门台→
   定位为访客→成员在线；全程 ≤5 分钟（relay 退避不计）。
3. **三视角一击切换**：右上角切换后首屏 3 秒答各视角首问（中枢四问/租约两问/
   到访两问）；三视角数据零串扰——租约页无 admin 概念，中枢页无成员倒计时；
   无管理凭证的设备打开 webui 直接落租约/到访视角（不进 setup）。
4. **「中枢不是流量瓶颈」可观察**：两台已直连成员互传中 `hub stop` → 互传不受
   影响；`hub start` → 新敲门可进。（先与技术设计对拍口径，不满足则 §1.2 文案
   收回——见 G-3。）
5. **重启回来**：开启自启→重启机器→中枢自动运行、托盘常态、无人工干预。
6. **租期闭环**：成员租约视角出现黄条倒计时与双路径续期指引；到期红标附新码
   重进命令；新码 join 后别名与门牌不变。
7. **机器名** [H6]：join 后管理台名册默认别名 = 成员机器名（可改）；`opendweb id`
   显示机器名；缩写并存且与 server-access-roles 全站一致函数同源。
8. **到访诚实呈现**：到访页脚 best-effort 声明常驻；「测一下」结果与实际一致；
   无记录/连不上时页面不虚造状态。
9. **契约回归**：server-access-roles 全部冻结面测试绿灯；新增面无「管理员」指代
   使用者等纪律违反；接入卡片三形态同源（改地址一次，三处同步）。

体验验收：按评审记分卡复评六维，平均 ≥8 且无核心维度 <7；发布会截图候选：接入卡片 + 三视角切换器展开态。

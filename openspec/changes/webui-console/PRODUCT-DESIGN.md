## 1. 产品界定

### 1.1 一句产品定义

**webui-console 是 Owner 的「服务器驾驶舱」：在你自己的电脑上，安全地回答「我的 dweb-server 还正常吗、谁在用它、谁能用它」，并在需要时收回访问。**

三个关键定位裁决：

1. **它是管理面，不是数据面。** 它操作的是准入（谁可以用）与连接（谁在用），永远不碰数据面凭证（spec 明令：UI MUST NOT 提供数据面授权判断入口）。这一点必须在界面语言上可感知——控制台的一切动词都是管理动词（注册、注销、断开），没有任何"使用网络"的动词。
2. **它是本地可信终端，不是网站。** 浏览器地址栏是 127.0.0.1，密钥只进本地进程、不进浏览器。这个安全模型是产品最大的差异化事实，当前 UI 只在配对面 hint 里提了一句——应该在首次引导中作为核心叙事讲清楚。
3. **它服务的动作频率是极度偏斜的：看 >> 管 >> 配。** 巡检是每次打开都发生的动作；注册/断连是偶发动作；配对一生一次。界面的人力分配必须服从这个频率分布（当前四页平级导航恰恰违背它）。

### 1.2 Jobs-to-be-Done（按频率 × 优先级排序）

| # | Job | 频率 | 完成判定 | 优先级依据 |
|---|-----|------|----------|-----------|
| J1 | **巡检**：打开即知「服务正常吗 / 谁在线 / 多少人可用」 | 每次打开（最高频） | 3 秒内、不滚动、不点击即可回答三问 | 每次会话的入口动作；答不出则其余一切功能无意义 |
| J2 | **准入管理**：决定谁能用这台服务器（注册 / 注销 Owner） | 中频（成员变化时） | 名册反映意图，注销后新连接即被拒，有回执为证 | restricted 模式的核心价值就是准入控制（server spec「Server 访问策略」） |
| J3 | **应急处置**：异常时断开连接、并确信动作已生效 | 低频高压 | 断连后看到收敛终态 + per-target 回执 | 出事时的心理负荷最高，最忌讳"不知道断没断成" |
| J4 | **首次接线**：把控制台与云端 server 安全配对 | 一生一次 | 落地总览页，且明白自己刚建立的是什么信任关系 | 一次性的，但失败/困惑发生在信任建立的最早时刻，伤害品牌 |
| J5 | **审计留痕**：变更后能出示服务端签名回执 | 低频（依附于 J2/J3） | 回执可复制全文，含签名 | spec 冻结契约（回执 SHALL 展示 op/ts/generation/签名摘要） |

### 1.3 使用叙事（三个场景的具体故事）

**叙事 A：第一次连接（对应 J4）**
Alice 在云端用 Docker 跑起了一台 dweb-server，配好了 `DWEB_ADMIN_TOKEN`。她在自己电脑上执行 `opendweb webui`，终端打印出一个本地地址和一行配对码，浏览器自动打开。她看到的不是一堆菜单，而是一页「把控制台接上你的服务器」的引导：告诉她这里是她电脑上的本地页面、密钥只交给本地进程、需要从终端抄三样东西。她照着 ①②③ 填完，点「连接并锁定」，页面明确告诉她目标已锁定、生命周期内不可改指。随后她落地在总览页——页面上写着服务器的模式、0 个 Owner、0 条连接，并提示她：「还没有任何 Owner 能使用这台服务器」，旁边就是去注册的入口。她不需要文档就明白了自己刚建立了什么、下一步该干什么。

**叙事 B：日常看一眼（对应 J1）**
Bob 的团队每天用这台服务器组网。他隔三差五、或队友说"连不上"的时候，打开书签里的控制台。页面打开即是总览：顶部一盏健康灯是绿的（管理面可达），下面一行关键数字——在线连接 2 条、Owner 3 个、受限模式、名册版本 v7。没有异常就关掉，全程 5 秒。他从来不需要点进任何子页面来完成"看一眼"。

**叙事 C：出事时处理（对应 J3 + J1 异常分支）**
Carol 的队友反馈连不上。她打开控制台，健康灯是红的，标题直接说「连不上服务器」，下面给出判别：是本地网络问题、远端宕机、还是管理密钥失效，并附上对应的下一步（重试 / 检查远端 / 带新密钥重启命令）。另一次，某个端点行为异常，她在「访问管理 → 在线」里找到它，点「断开」，确认对话告诉她将断几条连接、且断开是异步的；确认后同一位置出现进度，直到显示「已收敛」，附一张可复制的回执。她确信动作生效了，才离开页面。

### 1.4 产品模型（本节为仓库缺失的 PRODUCT_MODEL 首块，建议日后抽取为根目录 PRODUCT_MODEL.md）

```
对象模型（Entity / Ownership / Lifecycle / State）：

  Server（目标服务器，0..1 个，sidecar 生命周期内冻结）
    ├─ Owner 名册（N 条：(fabric, 根端点) 二元组；append-only 事件归并出活跃集）
    │    └─ 每次变更 ⇒ 名册版本 +1，产出签名回执
    ├─ 在线连接集合（动态；per-端点 × per-owner 投影；受每 owner 配额约束）
    └─ 运行配置投影（模式 / 策略 / relay 是否启用 / 配额）

旅程映射：
  首次接线（setup 世界，一次性）→ 巡检（ready 世界，默认落地=总览）
                                    ├→ 准入管理（名册 ⇄ 在线，同一对象两视角）
                                    └→ 应急处置（断连，收敛观测 + 回执）

导航收敛（One Concept → One Canonical Location）：
  - 「服务健康吗」真源 = 顶栏健康灯 + 总览页健康区（同一状态源，两处呈现）
  - 「谁可以用 / 谁在用」真源 = 访问管理页（名册 / 在线两个视角）
  - 「连的是哪台服务器、怎么换」真源 = 顶栏连接详情面板（掩码目标 + 重启指引）
  - 「我做过什么变更」真源 = 动作上下文内的回执（不另设全局审计页——本 change
    服务端无变更历史 API，UI 不得虚构历史）
```

为何先立模型再谈界面：当前 UI 的问题不是像素，而是**对象没有旅程**——四页各自渲染一个 API 端点，对象（Owner/连接）在页面之间没有叙事连续性。上面的模型决定 §3 的一切结构裁决。

## 2. 现状诊断

评审纪律：先写旅程链，按链走每一步。记分卡在末尾。

### 2.1 旅程链复盘（Owner 迷路的路径还原）

**链 1 · 首次连接（setup 态）**：终端打印 URL+配对码 → 浏览器打开 `#/connect` → 读 hint「从 sidecar 终端输出抄录一次性配对码…」→ 填三字段 → 提交 → 跳 `#/status` → 看到 8 张卡片。
断点：① 顶部导航有四个入口（配对/状态/Owners/在线连接），但点后三个全撞同一面「未连接」墙（`views.mjs` SetupGate，L169-181）——**导航承诺了四个目的地，实际只有一个可用**；② 成功后 `location.hash = "#/status"`（`app.mjs` L191）硬跳，没有任何「你刚建立了一段受信连接」的确认叙事；③ 落地的总览页 0 owner、0 连接，无下一步引导。

**链 2 · 日常巡检（ready 态）**：打开 → `#/status` → 8 张平级卡片里找 → 无健康结论。
断点：① 页面把 `cache_entries`（缓存条目）和「owner 数」放在同一视觉级别（`views.mjs` L332-365），没有人替 Owner 回答「正常吗」；② 轮询失败时错误横幅出现在卡片区上方，但**顶栏状态不变**（`app.mjs` L303-305 只有「已连接 host」一种正向呈现）——健康态不是常驻可见的；③ 「谁在线」在另一页（#/connections），巡检需要跨页拼接。

### 2.2 问题清单（按维度，均附实现证据）

**信息架构**

- **IA-1 导航按 API 端点分类，不按管理者任务。** `app.mjs` L32 `ROUTES = ["connect", "status", "owners", "connections"]` 与四个 HTTP 面（/sidecar/connect、/api/status、/api/owners、/api/connections）一一对应。用户心智里的任务是「看现状 / 管准入 / 换目标」，却要先学会工程的端点划分。导航标签「Owners」还是中英混排（L309）。
- **IA-2 「谁可以用」与「谁在用」被撕成两页，且无互链。** 同一个 fabric 在 owners 页（`views.mjs` L403）和 connections 页（L545/L567）各出现一次、都是 `shortHex()` 孤立显示，无跳转、无关联视觉。管理者对一个 Owner 的完整问题是「他有没有资格、他现在连着没有」，当前需要开两个页签人肉对 hex 前缀。
- **IA-3 配对面是常态导航项。** ready 态导航首位仍是「配对」（`app.mjs` L307），点进去是一页「已连接…目标已冻结」（`views.mjs` L238-251）——一次性流程占据了永久导航槽位，还排在第一位，直接制造「这界面是临时拼的」观感。

**流程**

- **FLOW-1 首次接线是「表单页」不是「引导」。** ConnectView（`views.mjs` L254-308）三输入框一按钮，无步骤结构、无安全模型叙事（仅一句 hint）、无成功过渡。setup 态的三个死胡同页（SetupGate）让导航 explor 变成惩罚。
- **FLOW-2 破坏性动作的确认对话不承载后果分级。** 注销 Owner 与断连共用同一个 Dialog 组件（`views.mjs` L184-197），按钮文案只差两个字；「断开是异步 best-effort、需要观测收敛」这一关键语义出现在**确认之后**的 hint 里（L514），确认时刻（最需要知情的时候）反而没说。

**文案**

- **COPY-1 工程术语裸露，无一处解释。** 卡片标签直书「模式（mode）」「策略（policy）」「generation」（`views.mjs` L338-347）；表头直书 `fabric_id` / `root` / `endpoint_id`（L395、L537）；确认对话里「(fabric_id, root) 二元组」（L462）。「generation 是什么」全界面零解释——而它恰是 Owner 核对「我的变更生效没有」的唯一凭据。
- **COPY-2 时间戳机器格式直出。** `new Date(o.registered_at).toISOString()`（L405）、回执 `ts` 同样（L203）→ 界面显示「2026-09-22T03:12:45.123Z」。对人类不可读，是"工程直出"最刺眼的签名。
- **COPY-3 空态是「（空）」。** owners 表空态 `<td class="empty">（空）</td>`（L399），connections 两处「（无在线连接）/（无在线 owner）」（L540、L563）。首次使用名册必空——这本是最好的教育时刻，却用两个括号打发。

**状态呈现**

- **STATE-1 无全局健康态。** 控制台最该持续回答的「服务正常吗」没有常驻答案位：顶栏 phase 只有正向「已连接」（`app.mjs` L303-305），轮询出错只在当前视图内挂横幅，切换视图即消失（每视图独立 error state，`app.mjs` L61-66）。
- **STATE-2 加载态是文本、布局跳变。** 「加载中…」纯文本（`views.mjs` L330、L528），数据 null 时卡片区整块消失再出现，5 秒轮询的页面每 5 秒潜在抖动一次（虽然数据在时不闪，首屏体验仍是"裸"的）。
- **STATE-3 回执的审计细节与关键信息同级。** ReceiptCard（L200-225）把「签名前缀 16 hex」与「时间 / 目标」并排展示。签名前缀对管理者是验签材料（复制全文时才用得到），把它放在第一层级强化了"这是给机器看的"观感。


## 3. 信息架构重设计

### 3.1 结构裁决（三问三答）

**问 1：配对面是否该是首次引导流而非常态页？——是。**
setup 态与 ready 态是**两个世界**：前者是「一次性建立信任」的仪式（全屏引导，无导航壳），后者是「日常管理」的驾驶舱（导航壳 + 多视图）。ready 态导航中不再有「配对」项；原配对面 ready 态承载的「目标已冻结、如何重指向」信息迁移到顶栏连接详情面板（§3.2）。旧路由 `#/connect` 在 ready 态自动收敛到连接详情，不留死页。

**问 2：status 是否该是首页 dashboard？——是，且要从「字段投影」改造为「健康结论」。**
总览页 = ready 态默认落地页，职责是 3 秒回答 J1 三问（正常吗/谁在线/多少人可用）。8 张平级卡片砍成有层级的结构：健康结论区 → 关键数字区 → 配置投影区（低层级，收纳 mode/policy/名册版本/配额/缓存等）→ 下一步引导区（空名册时）。`cache_entries` 这类实现细节降级到配置投影区尾部或删除呈现（数据仍在 API，UI 有权不展示；不违反契约——契约冻结的是行为，不是字段陈列）。

**问 3：owners + connections 是否合并为「访问管理」？——是。**
管理者心智里「谁能用我的服务器」是一个对象的两态（资格 × 在用）。合并为一页两视角（页内切换「名册 / 在线」），并建立对象互链：名册行的 fabric 与在线行的 fabric 是同一身份标识，视觉上同源（同一缩写规则+同一复制交互），从名册行可跳到在线视图过滤该 fabric。**这是把工程师视角的 API 划分改造成管理者视角的任务划分的核心一步。**

### 3.2 目标结构图

```

│  「把控制台接上你的服务器」                            │
│   安全叙事 + 三步指引（①地址 ②密钥 ③配对码）           │
│   提交「连接并锁定」→ 成功确认 → 自动进入 ready 世界     │
└──────────────────────┬───────────────────────────────┘
                       ▼
┌─ ready 世界（管理驾驶舱）──────────────────────────────┐
│ 顶栏：品牌 · [●健康灯+一句话] · 目标（点击→连接详情面板）│
│ ┌──────────┬────────────────────────────────────────┐ │
│ │ 导航(2项) │  总览（默认落地页）                       │ │
│ │  · 总览   │   健康结论 → 关键数字 → 配置投影 → 引导    │ │
│ │  · 访问管理│  访问管理                                │ │
│ │           │   视角① 名册（谁可以用）：列表/注册/注销    │ │
│ │           │   视角② 在线（谁正在用）：连接表/断连/收敛  │ │
│ └──────────┴────────────────────────────────────────┘ │
│ 连接详情面板（顶栏呼出，真源）：掩码目标 / 安全模型 /      │
│   重指向=重启指引 / 明文告警（insecure 时）               │
└───────────────────────────────────────────────────────┘
```

### 3.3 工程师视角 → 管理者视角映射（逐项理由）

| 现状（工程分类） | 重设计（管理任务） | 理由 |
|---|---|---|
| `#/connect` 常态导航首位 | setup 世界专属引导；ready 态并入顶栏连接详情 | 频率：一生一次 vs 每次打开（§1.1 裁决 3） |
| `#/status` 8 卡平铺 | 总览页四级层级（结论→数字→投影→引导） | J1 要求 3 秒出结论，不是 3 秒数完 8 个字段 |
| `#/owners` 与 `#/connections` 两页 | 访问管理一页两视角 + fabric 互链 | IA-2：对象同一，撕开是人肉拼接成本 |
| 错误横幅随视图出现/消失 | 传输级错误升级为顶栏健康灯（常驻）；动作级错误留在动作上下文 | STATE-1：健康是最全局的状态，不该被导航冲掉 |
| 回执卡片独立区块 | 回执跟随动作上下文（注册/注销/断连处就地展示） | 变更确认应在动作发生的视线焦点处 |

保留不动的契约面（重申）：二次确认、回执字段（op/时间/名册版本/签名摘要+复制全文）、断连四态收敛观测、token 不回显、明文持续告警、失败态矩阵语义——全部按冻结 spec 原样承载，只改组织与呈现。

## 4. 关键交互流（步骤 + 成品文案）

### 4.1 流 A：首次连接引导（setup 世界）

| 步 | 界面行为 | 成品文案 |
|---|---|---|
| 1 | 终端打印本地 URL + 配对码，自动开浏览器；页面为全屏引导（无导航） | 标题：**把控制台接上你的服务器**<br>副题：这个页面运行在你自己的电脑上，与云端的 dweb-server 之间隔着一条安全通道——管理密钥只交给本地进程，浏览器不保存、不回显。 |
| 2 | 引导列出三样输入的来源（都在终端） | 小节标题：**从终端抄三样东西**<br>① 服务器地址——形如 `https://srv.example.com:18787`<br>② 管理密钥（admin token）——服务器启动时设置的 `DWEB_ADMIN_TOKEN`<br>③ 配对码——终端最新打印的一行 13 位码，10 分钟内有效、只能用一次 |
| 3 | 表单三个字段分组编号 ①②③；密钥输入框 type=password | 字段标签：**① 服务器地址** / **② 管理密钥** / **③ 配对码**<br>配对码占位提示：13 位大写字母或数字<br>密钥占位提示：粘贴后立即交给本地进程，本页不留存 |
| 4 | 提交按钮；锁定语义前置披露 | 按钮：**连接并锁定**<br>按钮下方说明：连接成功后目标即锁定——本进程运行期间不能改指其他服务器；需要更换时，退出并在终端重新运行命令。 |
| 5a | 成功：短暂确认幕 → 自动进入总览 | 确认幕：**已连接。正在进入总览…**<br>（目标以掩码呈现，如 `https://***.example.com:18787`） |
| 5b | 失败：就地呈现，表单保留已填内容（密钥框除外——不回显），不整页报错 | 见 §5.3 错误文案全集之「配对面」组 |
| 6 | 落地总览（首次多为空名册），触发引导区 | 总览引导区文案见 §5.2「总览-空名册」 |

### 4.2 流 B：日常巡检（打开即答）

| 步 | 界面行为 | 成品文案 |
|---|---|---|
| 1 | 打开控制台 → 落地总览；顶栏健康灯常驻（5 秒轮询驱动，后台标签页暂停、回前台即刷） | 健康灯四态：<br>● 正常——**管理面连接正常**<br>● 异常——**连不上服务器**（网络/超时）<br>● 异常——**管理密钥无效**<br>● 异常——**远端未开启管理面** |
| 2 | 总览首屏（不滚动）给出结论区 + 关键数字区 | 结论区：**一切正常。2 条在线连接，3 个 Owner。**<br>（数字实时来自轮询；异常时结论区被健康说明替代，见流 C） |

### 4.3 流 C：异常处理（四类传输错误 + 断连）

**C-1 传输级错误（呈现在顶栏健康灯 + 总览结论区，全局常驻，不随导航消失）**

| 错误 | 结论区标题 | 结论区正文 + 动作 |
|---|---|---|
| network / timeout | **连不上服务器** | 到不了 `***.example.com`。可能是本地网络或远端宕机。<br>动作按钮：**重试**（自动每 5 秒重试中，上次失败 12:04:31） |
| unauthorized | **管理密钥无效** | 服务器拒绝了当前密钥。密钥在连接时已锁定，不能在本页更换。<br>正文：请退出本页，在终端用有效密钥重新运行：<br>`opendweb webui --token <新的管理密钥>`<br>（或按原启动命令重启） |
| admin-not-enabled | **远端未开启管理面** | 目标服务器没有配置 `DWEB_ADMIN_TOKEN`，管理接口处于关闭状态。<br>正文：请在服务器上设置该环境变量并重启，然后回到本页重试。动作按钮：**重试** |
| http-5xx | **服务器内部错误** | 远端返回了服务错误（502）。数据面可能仍在工作；持续出现请登录服务器检查。<br>动作按钮：**重试** |

**C-2 断连闭环（访问管理·在线视角内完成，不离开视图）**

| 步 | 界面行为 | 成品文案 |
|---|---|---|
| 1 | 在线表行内「断开」按钮 → 确认对话 | 标题：**断开这个端点？**<br>正文：将向服务器下发断开指令，端点 `a1b2c3d4…` 的 **2 条连接**会被关闭。<br>断开是异步的：确认后这里会显示进度，直到连接从在线表消失。<br>按钮：**确认断开** / **先不了** |
| 2 | 确认后原地出现进度态（沿用已实现四态机） | 徽章文案：**已下发** → **收敛中**（正在确认连接已断开，通常几秒内完成…） → **已收敛** / **超时未确认** |
| 3 | 终态 + 回执就地展示 | **已收敛**：该端点已从在线表消失。回执如下，可复制存档。<br>**超时未确认**：指令已下发，但 15 秒内在线表未观察到收敛。断开是尽力而为的——请刷新在线表核对；若连接仍在，可再次断开。 |
| 4 | per-target 回执（按 fabric 断开时逐端点一张） | 回执字段呈现见 §5.1（术语裁决后的标签） |
| 5 | 断连目标已不在线（no-match） | **这个端点已经不在线了**——可能刚好自行断开。在线表已刷新，请核对。 |

## 5. 内容设计

### 5.1 术语表（每个工程概念在 UI 上如何呈现——逐处裁决）

| 工程概念 | UI 呈现裁决 | 理由 |
|---|---|---|
| fabric_id | 主标签 **Fabric**；值一律缩写 `前 8 位 hex…`，点击复制全文，悬停显示全文。表头不再出现 `fabric_id` 字样 | 身份标识需要「认得 + 可复制」，不需要全文通读；裸 64 hex 是给日志的 |
| root | **根端点**（首现处补一句：该 Fabric 的根节点身份）。值同上缩写+复制 | 「root」单字在中文界面里歧义太大（系统 root？） |
| endpoint_id | **端点**；值缩写+复制 | 同上 |
| generation | **名册版本**（v 前缀呈现，如 v7）；悬停解释：「每次 Owner 名册变更后加 1，用于确认变更已生效」 | 这是 Owner 核对变更生效的凭据，必须可理解，不能是黑话 |
| registry | **Owner 名册** | 「注册表」在中文里会撞系统注册表 |
| Owner | 保留 **Owner**（产品专名，不大写翻译）。首现处定义：「Owner = 允许接入这台服务器的一个 Fabric 网络」 | server spec 明确区分 Server Admin 与 Relay Owner；译「所有者」会让 Admin 身份更混乱（证据：openspec/specs/server/spec.md「Server 身份与持久化」节） |
| mode: restricted / open | 徽章 **受限模式** / **开放模式**；受限悬停：「只有名册内的 Owner 可以接入」；开放模式在总览加说明行：「这台服务器未启用身份验证，任何人都能接入」 | 模式是安全姿态，值得徽章而非纯文本 |
| policy: static / callback | **准入策略：静态名册 / 动态回调**（配置投影区） | 低频信息，降级呈现 |
| admin token | **管理密钥（admin token）** | 「密钥」为主、「token」为辅注 |
| 配对码 | **配对码**；附有效期与一次性说明 | 已有，保持 |
| receipt_sig | 回执内降级为 **审计签名**（默认只显示「已含服务端签名」一行，完整签名进「复制全文」）；回执仍展示签名摘要（冻结契约不违反——摘要保留，层级降低） | STATE-3：验签材料是复制时用的，不是通读的 |
| kicked_connections | **一并断开的连接：N 条** | 动词化，说明发生了什么 |
| quota / max_connections_per_owner | **每 Owner 连接上限**；未配置时显示「未设置」 | 已接近正确，保持 |
| cache_entries | 从总览移除（不呈现） | 对管理者无决策价值；API 字段仍在，仅 UI 不陈列 |
| server_host_masked | 顶栏与连接详情呈现掩码值 | 冻结契约：完整 URL 永不进浏览器 |

hex 呈现通则（分层披露）：**浏览面**一律 `前 8 位 + …` + 复制 + 悬停全文；**操作面**（注册表单）保留 64 hex 完整输入与校验提示「需为 64 位十六进制字符（0-9 / a-f），可从成员管理处复制」。

## 6. 设计方向 brief（三个方向，请 Owner 拍板）

赛道判断（OJO Convention/Innovation 双赛道）：这是基础设施管理工具，价值在效用不在视觉体验——**Convention 赛道**，且证据把风格基调锁定在安静/专业区间（Energy: quiet；Finish: polished；Seriousness: solemn）。三个方向都在此区间内，差异在**密度、导航骨架、色彩性格**上——不是三个「简洁现代」的变体。

> **方向 A · 驾驶舱（Cockpit）**
> - 一句话主张：一屏就是一次巡检——总览即全部答案，管理动作一跳可达。
> - 视觉基调：高密度工作台。数据密度高、留白克制、等宽数字与对齐严格；近黑/纯白双主题、单一强调色；组件气质锋利精确（小圆角、细边框、无装饰）。
> - 布局骨架：顶部窄导航 + 全宽内容；总览页占据绝对 C 位，访问管理是唯一的一级子页。
> - 参考系：Vercel 控制台、GitHub 的 settings/insights 页（真实可查的开发者工具气质：信息密集但不喧哗）。
> - 适合判断：Owner 本人就是工程师、把控制台当日常工具高频打开的形态。牺牲：对非技术管理者不够亲和；视觉个性最低。
>
> **方向 B · 台账（Ledger）**
> - 一句话主张：这是一本可以审计的资产账——谁准入、谁在用、动过什么，一页一页翻得清楚。
> - 视觉基调：中等密度的管理后台。左侧导航 + 内容区，卡片分区块、留白从容；中性蓝灰底、语义色（成功/警告/危险）克制使用；组件气质稳重（中等圆角、清晰层级、表格精致）。
> - 布局骨架：左侧导航（总览 / 访问管理，为未来 owner-console 留扩展槽）+ 右侧内容；回执与名册的「可审计感」是第一设计价值。
> - 参考系：Stripe Dashboard（真实可查的管理后台标杆：把复杂状态讲得让非工程师也懂）。
> - 适合判断：把控制台视为「资产管理」界面、未来要接 owner-console 面向更多角色、受众可能不止工程师的形态。牺牲：首屏密度低于 A，纯巡检场景要多看一层卡片。
>
> **方向 C · 哨塔（Watchtower）**
> - 一句话主张：状态即界面——健康用颜色说话，正常时安静如灯，异常时一眼定责。
> - 视觉基调：低密度、大字报式状态页。健康灯与大号数字是第一视觉语言，语义色（绿/黄/红）承担主要信息层级；留白慷慨；组件气质简静（浅色为主、极少线条）。
> - 布局骨架：无侧栏；总览是近乎全屏的状态卡，管理动作收进次级视图。
> - 参考系：Grafana 的状态语义 + Things 3 的安静排版（取 Grafana 的「红黄绿即结论」，弃其仪表盘装饰；监控语义、非监控视觉）。
> - 适合判断：打开频率极高、每次只看 5 秒就走的「哨兵」用法；团队里多人共享查看权时状态无歧义。牺牲：管理操作（注册/断连）层级变深，操作效率让位于状态可读性；「低密度 + 大数字」对表格类信息（名册）不友好，需要 A/B 之一的密度观补课。

三方向真实取舍一览：密度（高 / 中 / 低）× 骨架（顶导航 / 侧导航 / 无侧栏）× 色彩性格（工具单色 / 商务中性 / 语义色主导）× 为谁优化（操作者 / 管理者 / 观察者）。拍板后视觉执行（token/组件/规范）由设计执行方按 OJO 流程产出，本文档不越界。

红线自检（anti-patterns）：三方向均无紫蓝渐变、无霓虹发光、无玻璃拟态科幻仪表盘；方向 C 的语义色仅用于状态结论，不做全屏染色。

## 7. 验收标准（重做后 Owner 如何判断「不再是 DEMO」）

结构验收（可当场检验）：

1. **两个世界分离**：setup 态看到的是无导航的全屏引导，不存在点得动的死胡同导航项；ready 态导航里没有「配对」；旧 hash（#/connect 等）在 ready 态自动落到正确去处。
2. **3 秒巡检**：打开总览，不滚动、不点击，能回答三问——服务正常吗 / 多少连接在线 / 多少 Owner 可用；顶栏健康灯常驻，轮询失败 5 秒内变色，切页不消失。
3. **术语零裸露**：界面正文与标签没有无解释的 `generation` / `policy` / `mode` / `cache_entries` 英文裸值；所有时间人类可读（本地时间 + 相对时间），无 ISO 8601 原文；身份 hex 一律缩写 + 复制 + 悬停全文。
4. **空态即引导**：名册空态提供「注册 Owner」动作；在线空态区分「无连接 / 中继未启用 / 开放模式无统计」三种文案。
5. **破坏性动作知情前置**：断连与注销的确认对话在确认时刻就写明范围（几条连接）、异步性（断连）与恢复路径；「先不了」是无压力选项。

# server-access-roles —— Owner 裁决（逐字存档）

> 本文件是 plan-mode 冻结裁决的逐字存档，为本 change 的最高需求信源；
> design/spec/实现只能引用，不得改写或重新解释。与后续裁决冲突时，
> 以更新的 Owner 裁决为准并在此追加。

1. **公钥即地址**：邀请只是传递公钥的通道，不是准入机制；持有 pubkey 即可敲门
2. **一台设备一个默认 key**（多密钥对=高级功能=切换设备指纹）
3. **访客准入 = 动态裁决**：管理员在 webui 看到敲门请求，当场定位成访客或租户
4. **租户邀请码**：包租婆签发，默认 1 次/7 天过期（times+deadline 可自定义），租户自助注册
5. **租户过期**：默认今天+30 天，可配置
6. **alias + 防钓鱼缩写**：`别名 (abc***xyz)`（区块链钱包式）
7. **节点切换**：右上角节点信息处切换，一次专注管一台，不做同屏多节点
8. **房门三制**：完全放行 / 租户名单 / 包租婆名单（+混合）

## 验收标准（可检验，源自批准的计划）

- 小白路径零文档可完成：陌生人连接被拒 → 包租婆在 webui 敲门台看到请求 →
  一键定位访客 → 对方重连即通
- 租户自助：拿到邀请码 → 客户端兑换 → 名册出现（带 alias/缩写/到期日）
- 到期租户连入被拒且 deny reason 明确；黑名单端点同票也拒
- 节点切换：右上角切换 → sidecar 重启指向新节点，凭证边界不变
  （token 不落浏览器）
- 既有契约全绿：sdk-mgmt-surface/webui-console 的全部测试面零回归；
  新 change strict 校验通过
